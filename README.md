# 143 OW Switch

Компактная утилита 143 Aim Club для Windows 10/11 x64. **BLOCK** блокирует диапазоны GEN1 только для Overwatch, **UNBLOCK** отключает правила приложения. C# / WPF / .NET 10.

## Установка и переход с 1.0

Скачайте `143OWSwitch.exe` из [последнего релиза](https://github.com/143kmh/143-OW-Switch/releases/latest), сохраните в постоянную папку и запустите. .NET включён. Подтвердите UAC; если автопоиск не найдёт игру, выберите `Overwatch.exe`. Есть поиск стандартных Battle.net-папок, сведений об установленной игре и некоторых Steam-папок; любая установка доступна через ручной выбор.

У exe нет цифровой подписи. SHA-256 находится в `143OWSwitch.exe.sha256`.

В 1.0 updater отсутствует: закройте старую версию через Tray → Exit, замените её новым exe и запустите. Настройки остаются в `%LocalAppData%\143OWServerSwitch`. Старые общесистемные блокировки группы приложения отключаются до выбора игры, затем заменяются правилами с полным путём к Overwatch.exe. Исторический адрес репозитория сохранён для совместимости ссылок.

## Поведение

BLOCK: исходящие Block-правила, все профили и протоколы, только выбранный Overwatch.exe и диапазоны GEN1. Другие приложения не затрагиваются. UNBLOCK отключает собственные правила и не отменяет ограничения других программ или политик.

Крестик скрывает окно в трей. ЛКМ открывает окно; ПКМ позволяет сменить режим, проверить обновления или выйти. **Exit сохраняет действующие правила**: чтобы снять блокировку, сначала выберите UNBLOCK.

Сохранённый режим восстанавливается при запуске. Отсутствующие и повреждённые правила исправляются, устаревшие удаляются, дубликаты устраняются. UI подтверждает режим после проверки записи. Ошибка сохранения настроек или firewall вызывает откат. Проверка каждые 10 секунд обнаруживает ручные изменения и неактивный firewall. Приложение не включает Windows Firewall и не меняет групповые политики.

Settings → Check rules проверяет путь, адреса, направление, действие, профили, протокол и режим. При проблеме появляется Repair. Remove firewall rules требует подтверждения, удаляет только собственные правила, отключает автозапуск и завершает приложение. Чужая группа с совпадающим именем вызывает отказ без изменения правил.

## servers.json и offline

[servers.json](servers.json) содержит серверные определения в CIDR. Текущие `34.88.0.0/16` и `35.228.0.0/16` перенесены из задания; принадлежность конкретному матчу и результат матчмейкинга не гарантируются.

При запуске мгновенно загружается валидный кеш, иначе встроенный конфиг. GitHub `main/servers.json` проверяется асинхронно. Новая дата `updated` → проверка → синхронизация правил → атомарное кеширование. При плохом JSON или ошибке записи остаётся рабочая конфигурация. Для публикации изменения увеличьте дату `updated` (YYYY-MM-DD); одинаковая дата игнорируется.

Проверяются schemaVersion, уникальность id, наличие GEN1, непустые серверы/ranges, корректность IPv4/IPv6 CIDR, сетевые адреса и дубликаты. Firewall получает диапазоны как данные. Текущий UI управляет GEN1; дополнительные определения пригодны для диагностики и будущих профилей.

GitHub недоступен → кеш; кеш отсутствует/невалиден → bundled config. Для BLOCK/UNBLOCK сеть не нужна.

## Диагностика

Detect current server сверяет PID и путь Overwatch, затем пять секунд получает **метаданные** событий Windows ETW. Содержимое пакетов не читается, не сохраняется и не меняется. Нет драйвера, hooks, чтения памяти игры или Battle.net API.

Наблюдаемое UDP-соединение вне известных CDN-диапазонов показывается как **CURRENT MATCH · CANDIDATE**: голосовой чат и другие соединения всё ещё могут дать ложного кандидата. TCP из ETW или резервной IPv4-таблицы всегда обозначается **AUXILIARY ENDPOINT**, с пояснением, что игровой UDP не наблюдался. Провайдер и город не угадываются по одному IP; повторяющиеся неизвестные поля скрыты. Обычная Windows UDP-таблица не содержит удалённого адреса.

Cloudflare определяется локально по снимку официальных [IPv4](https://www.cloudflare.com/ips-v4) и [IPv6](https://www.cloudflare.com/ips-v6) диапазонов от 2026-09-23. Такие адреса показываются только как вспомогательная инфраструктура, включая UDP, без предположения о городе. Классификация не делает новых сетевых запросов и никогда не используется в firewall.

[Google Cloud IP list](https://www.gstatic.com/ipranges/cloud.json) используется только для региона, кешируется на сутки и сопоставляется локально. Обнаруженный IP никуда не отправляется. `europe-north1` отображается как Finland. Список Google **никогда не изменяет firewall**. Copy server info копирует отчёт в буфер обмена.

## Обновления

Automatically check for updates проверяет GitHub Releases API один раз при запуске. Есть ручная проверка в Settings и трее. Поддерживаются стабильные semantic версии `vMAJOR.MINOR.PATCH`; draft и prerelease не устанавливаются. Предложение обновиться не блокирует главный экран.

Update повторно получает метаданные, скачивает `143OWSwitch.exe` и `.sha256`, проверяет SHA-256, размер, ProductName и версию. Подготовка идёт в защищённой `%ProgramFiles%\143 OW Switch Updates`, доступной администраторам и SYSTEM. Копия текущего exe ждёт выхода приложения, атомарно заменяет файл с резервной копией и запускает новую версию. Нет подтверждения успешного старта → откат. При успехе временные файлы удаляются. Config, firewall и настройки автозапуска сохраняются.

SHA-256 проверяет целостность, но не заменяет подпись издателя: источник доверия — HTTPS и этот GitHub-репозиторий. Репозиторий публичный; GitHub-токены приложению не нужны.

## Автозапуск и данные

Run on startup: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение `143OWServerSwitch`. Без служб и планировщика. При входе требуется UAC; Start minimized скрывает окно, но не UAC. После переноса exe запустите его: включённая запись обновится.

Elevation рассчитан на ту же учётную запись. Если вводятся данные другого администратора, HKCU и настройки будут принадлежать ему.

`%LocalAppData%\143OWServerSwitch\config.json`: режим, путь к игре, запуск, уведомления, проверка обновлений и позиция окна. `servers.json`: кеш определений; `google-cloud.json`: кеш диагностики; `logs/`: два ротируемых файла примерно по 512 KiB.

Нет телеметрии и аналитики. Запросы идут только к GitHub для конфигурации/обновлений и Google для диагностики. Никаких VPN, proxy, overlay или модификаций игры.

## Сборка

Windows + .NET 10 SDK:

```powershell
./build.ps1
```

Результат: `artifacts/143OWSwitch.exe` и checksum. GitHub Actions запускает тесты и сборку; push тега `v*` создаёт релиз с двумя файлами, если релиз ещё не существует.

```powershell
dotnet run --project tests/Excluder.Tests -c Release
dotnet publish src/Excluder.App -c Debug -o debug-preview
./debug-preview/143OWSwitch.exe --preview
```

Preview существует **только в Debug**: правила в памяти, отдельный config в `%TEMP%`, без системных изменений и сетевых проверок. Production не включает этот режим.

Диагностика использует [Microsoft.Diagnostics.Tracing.TraceEvent](https://github.com/microsoft/perfview) под MIT. .NET runtime поставляется вместе с приложением. [CHECKLIST.md](CHECKLIST.md) содержит выполненные и ручные проверки.
